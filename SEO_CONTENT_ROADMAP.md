## Tier 2 — Build as inventory grows

- Color laser, monochrome laser, inkjet, all-in-one and photo-printer landing pages: each needs representative inventory, unique buyer questions, real classification and a distinct query assignment. One printer may belong to multiple verified categories; type and function are different dimensions.
- HP PageWide/LaserJet, Lexmark CS, Brother HL/MFC and Canon SELPHY families: one reviewed family at a time, with real examples, verified supply/driver caveats and links to exact units. Do not turn every series prefix into a page.
- Olympus Stylus/Tough and Pentax Optio pages: split from existing hubs only when inventory and first-hand content justify it. Strengthen the existing Kodak EasyShare and Casio Exilim pages before considering further splits. Redirect only actual superseded equivalents.
- Battery and old-memory-card guides: exact model-to-part mapping sourced to manufacturer manuals, source URL/page, verification date and reviewer. Distinguish capacity, format, voltage, region and connector where applicable. Offer no compatibility guarantee from a brand match.
- Printer toner/drum explainer: illustrate consumable roles with real photos, distinguish included supplies from required replacements, link real supply inventory only.
- Improve product photography: front/back, ports, model label, included items, defects and printer test output when available. Rename new uploads descriptively; preserve old image URLs unless a safe migration is justified.

## Editorial release gate

A named editor verifies facts against manufacturer documentation and actual units. Store source URL, manual page, date, model/region and reviewer for model specifications. Keep shared model facts separate from unit-specific condition, price, accessories and testing. Mark unknowns explicitly. Draft structured data from the same visible facts. Include author, honest update date, useful representative image/alt, category/brand/family links and a return link from the parent. Test mobile readability, one H1, heading order and link destinations. Review sitemap/indexability, canonical intent and feed consistency. Publish a small cluster, measure, then expand.

Model-data evolution: keep using model/productType/testing/included/flaws/storage fields and verified MPN/GTIN now. Design a sourced model registry before adding sensor/megapixel/battery or printer duplex/network/toner/function fields. Do not populate new fields by guessing or automatically scraping low-quality sources. No schema migration is necessary for this phase.
